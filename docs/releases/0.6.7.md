# Conan Code 0.6.7

Fixes an intermittent embedded-terminal sizing bug: the terminal pane could
render at the wrong size relative to its own slot — text cut off on both
edges, or bleeding into the tab strip above or the prompt input below —
especially right after a window resize, sidebar drag, or split resize.

## Terminal sizing fix

`GhosttySurfaceView` resized Ghostty's grid from its own `NSView.bounds`
inside `layout()`. AppKit can update that `bounds` on its own schedule,
sometimes a frame or more after SwiftUI has already committed to a new size
for the pane during an animated or fast-moving resize. Resizing Ghostty
against that stale `bounds` produced a grid that did not match the pane's
real on-screen size until a later, unrelated layout pass corrected it — the
visible symptom the user reported.

`TerminalSurfaceRepresentable` now wraps its `NSViewRepresentable` in a
`GeometryReader` and feeds that reader's reported size into
`GhosttySurfaceView.sizeDidChange(_:)` on every `makeNSView`/`updateNSView`
call, instead of the view computing it from `self.bounds`. This mirrors the
approach the official Ghostty macOS app uses around `libghostty`, which does
not read `NSView.frame`/`bounds` for the same reason.

- `Coinor/Terminal/TerminalSession.swift`: `TerminalSurfaceRepresentable` is
  now a `View` wrapping a `GeometryReader` around the private
  `NSViewRepresentable` (`TerminalSurfaceHostingView`), which passes the
  reader's size straight through. No call site changed.
- `Coinor/Terminal/GhosttySurfaceView.swift`: added `sizeDidChange(_:)` and a
  `hostSize` property; `updateSurfaceSize()` now converts that host-reported
  point size to backing pixels instead of `self.bounds`, falling back to
  `bounds` only if no host size has arrived yet (e.g. before the first
  `GeometryReader` pass).

## Ghostty artifact manifest

The bundled `GhosttyArtifactManifest.txt` had drifted from the verified
`Vendor/Ghostty` artifact on this machine: same pinned tag/commit
(`v1.3.1` / `332b2aefc6e72d363aa93ab6ecfc86eeeeb5ed28`) and header/resources
hashes, but a different `library_sha256`/`xcframework_sha256` from a later
local rebuild of that same pinned source. `scripts/ghostty/verify.sh
--artifact-root Vendor/Ghostty` confirmed the on-disk artifact is internally
consistent and correctly pinned, so the committed manifest was regenerated
from it (`cp Vendor/Ghostty/manifest.txt
Coinor/Resources/GhosttyArtifactManifest.txt`), the same step
`scripts/ghostty/install-app-artifact.sh` performs. No Ghostty source, tag,
or commit changed.
