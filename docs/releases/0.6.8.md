# Conan Code 0.6.8

Hardens the embedded terminal against the sizing corruption 0.6.7 tried to fix
and did not: the terminal pane could render on top of the tab strip above it
or the prompt input below it, with clipped/misaligned text, confirmed
reproducing on an external non-Retina monitor after 0.6.7 shipped.

## Root cause, revised

0.6.7's diagnosis (AppKit's `NSView.bounds` lagging SwiftUI's own layout) was
real but incomplete. SwiftUI does not clip an `NSViewRepresentable`'s content
to its allotted frame by default, and nothing in `GhosttySurfaceView` clipped
its own rendering either. Ghostty's renderer can briefly hold a frame sized
for the surface's previous geometry while a resize is catching up; with
nothing clipping that content, it painted straight past the pane's own
boundary into whatever sits next to it. A discrete resize event forced a full
relayout that reset the correct bounds and self-healed the symptom, which is
why it looked intermittent rather than being a genuine size-calculation bug.

## Fix

`Coinor/Terminal/TerminalSession.swift` adds `TerminalClippingContainer`, a
thin `wantsLayer = true` / `layer.masksToBounds = true` `NSView` that
`TerminalSurfaceHostingView` now returns instead of the raw `GhosttySurfaceView`
(or `TerminalErrorView`), hosting it as a bounds-pinned subview. Clipping
happens at this ancestor regardless of what layer Ghostty itself ends up
owning on the surface view, including if it replaces that view's layer
outright. `GhosttySurfaceView` also masks its own layer directly as a first
line of defense.

0.6.7's `GeometryReader`-driven sizing (`sizeDidChange(_:)`) is kept; it is
still architecturally correct and did not regress anything.

## Validation

- `scripts/dev/preflight.sh` passed on the pinned toolchain.
- `scripts/dev/run-tests.sh` ran the full suite; the pre-existing,
  load-sensitive subprocess wall-clock timing flakes
  (`executableVersionProbeRejectsEmptyVersionOutput`,
  `GitProcessRunnerDeadlineTests.oversizedOutputIsTruncatedThroughTheGitRunner`)
  intermittently missed their bound only under full-suite background load and
  passed individually in isolation; `git diff` against every file behind
  those tests is empty.
- `GhosttySurfaceResizePolicyTests`, `GhosttySurfaceHandleTests`,
  `TerminalSessionFocusTests`, and the rest of the terminal/mouse/keyboard
  suites passed.
- The arm64 Release build succeeded. `scripts/release/verify-app.sh` reported
  version `0.6.8 (46)`, arm64, macOS 13.0 minimum, deep-strict ad-hoc
  signature, App Sandbox disabled, `get-task-allow` absent, and Ghostty commit
  `332b2aefc6e72d363aa93ab6ecfc86eeeeb5ed28`.
- `git diff --check` passed; `scripts/release/security-scan.sh` passed over
  the tracked snapshot and every file in the release bundle.

Manual verification specifically targeted the environment where 0.6.7 still
failed: the user's actual external monitor (a 5120x1440 display at 1.0 backing
scale, versus the built-in display's 2.0), which 0.6.7's verification never
exercised. Against the installed 0.6.8 build on that monitor: repeated rapid
window resizes (randomized sizes, back to back, no settle time), tab
switching while a pane was hidden and mid-resize, sidebar toggling, and
repeated window moves across the display boundary between the two monitors —
all with a real Grok conversation streaming output in the background — none
reproduced the corruption. The same stress sequence reproduced it once before
this fix (screenshot on file from that reproduction) and did not reproduce it
after.

Apple Silicon running macOS 13 or newer.
