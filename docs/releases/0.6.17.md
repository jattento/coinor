# Conan Code 0.6.17

Fixes the last cause of the misaligned window: a Browser Mirror tab's live
screenshot could report a width far larger than the pane it lives in, and
that measurement pushed the sidebar off the left edge of the window and the
terminal past the right one.

0.6.16 fixed the split itself — the sidebar and the detail column are laid
out explicitly and can no longer overlap. It did not stop a view *inside*
the detail column from reporting a size larger than the column, which is
what this release fixes.

## Root cause, measured

The live broken window, through the accessibility API:

```
WINDOW                        x=-1700  w=1688
  AXHostingView               x=-1700  w=1688
    AppShellActivityStackPanel  x=-1942  w=278   ← 242pt left of the window
    AppShellTerminalRegion      x=-1663  w=1893  ← 484pt wider than its column
      conversation.tabs         x=-1663  w=1893
        terminal-tabs.bar       x=-1663  w=1893
```

The sidebar plus the divider plus the detail column measured
`278 + 1 + 1893 = 2172` in a 1688-wide window. The hosting view centres
content it cannot fit, so everything shifted left by `(1688 - 2172) / 2 =
-242`: the sidebar left the window entirely and the terminal ran 242 points
past the right edge.

Closing the Activity Stack panel while the window was still broken made the
detail column grow to 1949 — because removing the action bar gave the pane
37 more points of *height*. Width tracking height is the signature of an
aspect-ratio-locked view, and the numbers are exact:

| pane height | detail width | width / height |
| --- | --- | --- |
| 1262 | 1893 | 1.5 |
| 1299 | 1949 | 1.5 |

3:2 is the shape of the screenshots `ego lite` captures. The culprit is the
Browser Mirror tab's frame:

```swift
Image(nsImage: image)
    .resizable()
    .aspectRatio(contentMode: .fill)
    .frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .top)
    .clipped()
```

`.aspectRatio(contentMode: .fill)` reports the size needed to *cover* the
offered space, so in a pane taller than 3:2 it reports `height × 1.5`.
Neither of the two modifiers that look like they contain it actually does:
a flexible `.frame(maxWidth: .infinity)` reports whatever its child returns
whenever the child returns more than was proposed, and `.clipped()` only
trims drawing, never layout. The inflated width therefore travelled up
through the tab stack, the conversation pane, the detail column and finally
the window content.

Every mounted tab is measured, visible or not, so an open Browser Mirror tab
broke the window from a background tab as well.

## Fix

- `BrowserMirrorView` draws the screenshot as an overlay on its background
  colour instead of as a `ZStack` sibling. An overlay never changes the size
  its parent reports, so the fill-and-crop behaviour is unchanged while the
  measurement no longer escapes the tab.
- New `PinnedStack`, a `Layout` that proposes and reports exactly the space
  it was offered regardless of what its children return. It replaces the two
  `ZStack`s that keep every conversation and every tab mounted
  (`RuntimeHostView`, `ConversationTabbedView`) and wraps the detail column
  in `AppShellView`. This is the containment the previous releases believed
  `.frame(maxWidth: .infinity)` provided.

## Tests

- `CoinorTests/BrowserMirrorLayoutTests.swift` measures the real views with
  `NSHostingController.sizeThatFits(in:)`: a Browser Mirror tab holding a
  1500×1000 frame, offered a 400×600 pane, must report exactly 400×600, and
  so must a `PinnedStack` wrapping an aspect-fill image. Reverting only
  `BrowserMirrorView` and re-running the test reproduces the bug exactly —
  it reports 900 instead of 400, `600 × 1.5`, the same arithmetic the live
  window showed at `1262 × 1.5 = 1893`.
- `AppShellUITests.testSidebarAndTerminalRegionTileTheWindowExactly` asserts
  the sidebar starts at the window's leading edge and the terminal region
  ends at its trailing edge.
