# Conan Code 0.5.3

Conan Code's embedded terminal now has its own theme instead of inheriting
whatever the host Mac's general Ghostty install happens to use.

## Highlights

- `GhosttyOverrides.conf` now sets an explicit background, foreground,
  cursor, selection, and full 16-color palette instead of only
  `mouse-shift-capture`. Because it loads after Ghostty's default and
  recursive config search, it fully overrides the shared Ghostty config for
  Conan Code only; `~/.config/ghostty` and the standalone Ghostty.app's own
  Application Support preferences are untouched.
- The palette is sampled directly from the Codex desktop app: a neutral
  near-black background (`#181818`), a slightly lighter neutral gray for
  `black` (`#2d2d2d`), off-white primary text (`#e8e8e8`), and the same
  muted accent colors Codex already uses for diff stats and status (sage
  green, coral red, amber warning, sky-blue notification).
- The main pane, IDE pane (`fresh` + `lazygit`), and any additional shell
  tabs all share this one theme, since every embedded Ghostty surface is
  created from the same app-wide `GhosttyRuntime`/`GhosttyConfiguration`.

## Compatibility

- The application bundle remains `Coinor.app`, with bundle identifier
  `dev.coinor.Coinor`, executable `Coinor`, and existing Application Support
  paths.
- Existing metadata remains compatible.
- The bundled Ghostty dependency remains pinned to v1.3.1.

## Verification

- 216 unit, integration, and XCUITest cases passed with no failures or
  skips.
- Loaded `GhosttyOverrides.conf` through the real GhosttyKit C API
  (`ghostty_config_load_default_files` -> `load_recursive_files` -> this
  override -> `finalize`) on top of the machine's live Ghostty config: 0
  diagnostics, and every color resolved to the intended value.
- Rendered the palette with an isolated, throwaway GhosttyKit-linked preview
  window (not the shipped Phase 0 spike and not the installed application)
  to confirm it renders cleanly with the real Metal renderer before it went
  anywhere near the shared config or the shipped app.
- `scripts/phase0/check-boundaries.sh` passed with the canonical sibling
  `grok-build` checkout supplied through `GROK_BUILD_ROOT`.
- `scripts/ghostty/verify.sh --artifact-root Vendor/Ghostty` passed for
  Ghostty tag `v1.3.1`, commit `332b2aefc6e72d363aa93ab6ecfc86eeeeb5ed28`.
- `scripts/release/verify-app.sh` passed for the exact Release bundle.
- `scripts/release/security-scan.sh` found no secrets or private local paths
  in Git history, the publishable source snapshot, or the Release bundle.
- `git diff --check` passed.
- The archive checksum verified, and `diff -qr` found no difference between
  the built and archive-extracted application bundles.
- Manual visual QA opened the exact Release bundle: the IDE pane (`fresh` +
  `lazygit`) rendered the new neutral palette cleanly against the sidebar,
  and the app restored the same live conversations and Grok sessions that
  were running before the rebuild.

The application is ad-hoc signed and not notarized. It is intended for the
owner's Apple Silicon Macs rather than Mac App Store distribution.
