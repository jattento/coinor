# Conan Code 0.6.11

Fixes a severe Activity Stack bug: heavy use (repeatedly opening and closing
the panel) could freeze the app and force a quit.

## Root cause

The Activity Stack's detail view mounted its own separate `RuntimeHostView`
instance in place of the normal `ConversationContentView` whenever the panel
opened, then swapped back on close. SwiftUI treats those as two different
view identities in two different tree positions, so every single open/close
tore down and relaunched **every tab of every loaded conversation** — not
just the focused one. Each tab is backed by a real `ghostty_surface_t`: a
real subprocess and a real GPU-backed rendering surface, not inert view
state. Toggling the panel repeatedly piled up teardown/relaunch cycles faster
than they could complete, which is what showed up as a freeze requiring a
force-quit — not a classic memory leak, but the same symptom: unbounded
process/resource churn from something that should have been free.

## Fix

`AppShellView` now keeps exactly one `ConversationContentView` (and its
`RuntimeHostView`) mounted at a fixed position in the view tree at all times,
regardless of whether the Activity Stack is open. The panel's UI
(`ActivityStackEmptyOverlay`, `ActivityStackActionBar`) is now pure chrome
laid over and under that same always-mounted terminal — it never creates a
second `RuntimeHostView`. Focusing a conversation from the panel still goes
through the same `AppCoordinator.selectConversation` a sidebar click uses, so
the terminal already shows the right conversation on its own.

The sidebar's own swap (Pinned/Projects list ↔ the queue) is unaffected and
unchanged: it is ordinary SwiftUI list content with no native backing
resources, so repeating it is cheap.

## Validation

- `scripts/dev/preflight.sh` passed on the pinned toolchain.
- `scripts/dev/run-tests.sh` ran the full suite; the same pre-existing,
  load-sensitive subprocess wall-clock timing flakes documented for earlier
  releases missed their bound only under heavy background load and passed
  individually in isolation; `git diff` against every file behind those
  tests is empty.
- Live verification against a real, already-resumed Grok conversation (not
  just a Debug build smoke test): captured the PIDs of its terminal
  processes (main session, `lazygit`, `fresh .`), toggled the Activity Stack
  20 times in rapid succession (~4.4s wall time) via accessibility-driven UI
  automation, and confirmed every one of those PIDs was still alive and
  unchanged afterward — proving no surface or subprocess was torn down and
  relaunched. Screenshots before, during (empty-state overlay), and after
  toggling showed the terminal's content pixel-identical, confirming no
  visual regression from the restructure.
- The arm64 Release build succeeded; `scripts/release/verify-app.sh`
  reported version `0.6.11 (49)`, arm64, macOS 13.0 minimum, deep-strict
  ad-hoc signature, App Sandbox disabled, `get-task-allow` absent.
  `scripts/release/security-scan.sh` reported no leaks.
