# Conan Code 0.5.13

Conan Code can now work on projects that live on another Mac. A remote
project's conversations, subagents, IDE tools, and shell tabs run on that
computer while every terminal surface stays local.

## Highlights

- Remote computers are registered from the `Host` entries of `~/.ssh/config`.
  Conan Code stores only the alias: no user, port, key path, or credential.
- Remote execution is plain `ssh` invocation of the same commands the local
  path already runs. Conan Code adds no daemon, no network listener, and no
  protocol of its own. All channels for one host share a `ControlMaster`
  connection.
- Registering a host runs the same compatibility contract the local runtime
  runs at start-up, in one SSH round trip: home directory, Grok executable,
  `grok --version`, runtime socket, and the host's `MaxSessions`. The base
  Grok version must match; a differing overlay build warns instead of
  refusing.
- Each host runs its own Grok leader on a socket separate from the one that
  computer's own Conan Code uses, so neither installation can terminate the
  other's runtime.
- Work continues on the remote computer when the connection drops or Conan
  Code quits. A pane whose `ssh` exits 255 reconnects with bounded backoff and
  then offers an explicit `Reconnect`.
- Remote projects appear in the same flat `Projects` list with a host badge
  that turns red while the host is unreachable. Their conversations stay
  listed rather than disappearing.
- Adding a remote project never requires typing a path: Conan Code offers the
  repositories that host's Grok catalog already knows plus a bounded scan,
  with a remote directory browser as a fallback.
- `In New Worktree` runs the fetch, default-branch resolution, and worktree
  creation on the remote host, using that computer's Git credentials.

## Compatibility

- Project identity is now host-qualified for remote repositories. Local
  identities keep their previous bare-path representation, so existing
  metadata resolves unchanged.
- Metadata schema version 4 adds the registered host aliases. Older documents
  migrate with an empty list.
- Agent-managed terminal tabs remain local-only. A remote agent inherits
  neither the control socket nor the instance token, so that skill fails
  closed and the agent uses Grok's ordinary terminal tool.
- The application bundle remains `Coinor.app` with its existing bundle
  identifier and local data paths.

## Verification

- The full Debug test suite passed with 0 failures.
- The arm64 Release build and `scripts/release/verify-app.sh` passed.
- `scripts/release/security-scan.sh` found no secrets or private local paths.
- Live verification against a real second Mac: the probe, the ACP handshake
  and session roster over SSH, a remote leader that survived the closed SSH
  channel with `PPID 1`, its isolation from that computer's own Conan Code
  leader socket, and a clean remote runtime stop.
