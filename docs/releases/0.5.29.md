# Conan Code 0.5.29

This release adds a native Grok Workflows center, fixes working-state aggregation for live subagents, preserves fuzzy-search text when switching to Agent Search, and requires the matching private Grok Build overlay release.

## Native Grok Workflows

- A first-class `Workflows` destination discovers project, personal, built-in, and forward-compatible workflow definitions for the last selected conversation.
- Launches support friendly key/value arguments, advanced raw JSON, and explicit agent budgets from 1 through 1,024.
- Runs update live with status, phases, agents, elapsed time, budget usage, events, pause reasons, and results.
- Pause, resume, stop, and higher-budget resume controls appear only when valid. Budget-limited runs cannot send an invalid bare resume.
- Loading, empty, failed, paused, blocked, interrupted, budget-limited, completed, cancelled, and unknown future states remain distinct and inspectable.
- Grok owns scripts and authoritative run state; Conan Code owns responsive native presentation and forwards intent over the private ACP control connection.

## Reliability fixes

- A live working subagent keeps its conversation and project activity indicator working while the root agent is idle. `needsInput` still has precedence, and finishing the last child clears working unless the root remains active.
- Enabling `Search with Grok` carries the fuzzy query byte-for-byte and submits it exactly once when nonempty after trimming. Whitespace-only text, dismissal, and repeated toggles do not create duplicate requests.
- Workflow updates are revision-gated per run, while runs are ordered by Grok event time rather than incomparable per-run revisions.
- Late workflow responses cannot write errors or state into a different conversation after the user switches context.
- Structured Grok workflow errors show their actionable message instead of a raw JSON envelope.

## Requires

- `~/bin/grok` from `jattento/grok-build` `v1.0.3-overlay.2` or newer.
- macOS 13 or newer on Apple Silicon.
