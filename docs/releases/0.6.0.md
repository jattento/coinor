# Conan Code 0.6.0

Adds **Automations**: scheduled Grok prompts that run on their own, in a
project you choose, each firing opening a brand-new conversation.

## Automations

A new Automations tab in the sidebar. An automation is a prompt, a schedule, a
project and a model. Every time it fires, it starts a fresh Grok session that
appears in the sidebar under its project, marked with a clock badge.

**Scheduling is macOS's, not Conan Code's.** Each automation installs its own
launchd job whose calendar intervals are compiled from the schedule. That means
no background helper process and no polling, and it is what gives the feature
its catch-up behaviour: launchd runs a job that was missed while the machine was
asleep or powered off, and folds several missed occurrences into a single run.
An automation that should have fired ten times while the Mac was off runs once,
for the most recent occurrence, rather than replaying the whole backlog.

**Runs are `grok` itself.** The job invokes the installed Grok executable
directly in headless mode, so no Conan Code process has to be running:

```
grok --cwd <project> --session-id <uuid> --rules <shared prompt> \
     [--model <model>] --always-approve -p <prompt>
```

The shared instruction is appended to Grok's own system prompt rather than
replacing it, so the agent keeps its tools and behaviour, and permission
prompts are pre-approved so an unattended run cannot block on one. The run is a
single user turn, after which the agent runs its full loop — tools, subagents
and all — until it finishes.

### Schedules

Schedules are chosen with a recurrence picker rather than typed as cron: every
few minutes, hourly, daily, weekly on chosen days, monthly, each with a time
picker, plus a custom mode that still accepts a raw expression. The editor
shows what the schedule means in words and when it will next run. A hand-written
expression the picker cannot describe is preserved untouched.

### The tab

The Automations tab lists every automation and shows the selected one in
detail: its schedule, next run, project, model and prompt, and every execution
newest first with status, duration, whether it was scheduled or manual, and a
link to open the conversation it created. Automations can be run immediately,
paused, resumed, edited and deleted; pausing unloads the launchd job, so a
paused automation neither fires nor catches up.

Each finished run raises a native notification, and its conversation is named
after the automation that produced it.

## Other changes

- `MetadataStore` gained a reload-before-write path, so a writer never
  overwrites a change it has not seen.
- The cron parser accepts named ranges such as `MON-FRI` and `JAN-MAR`.

## Compatibility

The metadata document moves to schema 7. Documents written by earlier versions
load unchanged, and automation state is only written once an automation exists.

## Validation

- Debug build, Release build, and bundle verification on the pinned toolchain.
- Full test suite: unit and user-interface tests, with no regressions.
- Live launchd test that installs a job, starts it through the same control the
  Run Now button uses, and reads the recorded run back.
- Security gate over Git history, the working tree, and the application bundle.

## Artifact

`Coinor-0.6.0-arm64.zip` is an ad-hoc signed, non-notarized personal build for
Apple Silicon running macOS 13 or newer.
