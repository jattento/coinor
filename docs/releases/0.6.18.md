# Conan Code 0.6.18

Adds point-to-code: Grok can point you at a specific range of code, with an
explanatory comment, instead of only describing a location in prose. See
ADR 0019.

## Point to code

Grok can call a native tool, `point_to_code`, that opens the IDE tab's
`fresh .` editor at a specific file and line range with a one-step guided
tour: the range highlighted, and Grok's comment shown alongside a step
navigator. The agent decides when this is useful on its own; there is no
Coinor UI control for it.

No MCP server is involved. The tool lives in the user's own fork of the
Grok CLI, `github.com/jattento/grok-build`, and is listed to the model only
when `CONAN_CODE_CONTROL_SOCKET`, `CONAN_CODE_CONTROL_TOKEN`, and
`CONAN_CODE_SESSION_ID` are present on the root Grok process — which Coinor
now injects for local, non-remote conversations only. When called, it opens
a raw connection directly to Coinor's existing private terminal-control
socket (ADR 0013) and sends a hand-encoded request matching
`TerminalControlContract` exactly, since the two repositories share no
compiled contract.

A new Fresh editor plugin, `conan-code-tour` (installed by a new
`FreshPluginInstaller`, mirroring `GrokSkillInstaller`'s atomic-write
behavior), polls the same control socket from inside the IDE tab's `fresh .`
process and opens the result through Fresh's own bundled `code-tour` plugin.

This was validated live, end to end, inside a running Coinor conversation:
without the three environment variables, the tool is not listed to the
model at all; with them, a real prompt caused Grok to call `point_to_code`,
and the IDE tab opened the named file with the requested lines highlighted
and the comment visible, matching the mockup this feature was built from.
One interaction nuance surfaced during that verification and is documented
in ADR 0019: a second `point_to_code` call does not replace an
already-open tour until the current one is finished (`q`).

This is phase 1 of a three-phase plan; multi-step tours and user-left
comments Grok can read back are not yet built.

## Validation

- `scripts/dev/preflight.sh` passed on the pinned toolchain.
- `scripts/dev/run-tests.sh` ran the full suite; the pre-existing,
  load-sensitive subprocess wall-clock timing flakes
  (`executableVersionProbeKillsACommandThatWouldOtherwiseHang`,
  `GrokSubprocessTransportShutdownTests.shutdownWaitsUntilTheChildProcessHasExited`)
  intermittently missed their 2-second bound only under heavy background
  load and passed individually in isolation; `git diff` against every file
  behind those tests is empty.
- New `terminalControlRequestDecodesPointToCodeFields` and
  `terminalControlRequestDecodesTourWaitWithOnlyASessionID` cover the two
  new terminal-control methods' wire decoding.
- On the `grok-build` fork: `cargo test`, `cargo clippy --all-targets`, and
  `overlay/scripts/overlay-diff.sh` (touchpoints documented, delta budget
  held) all passed for the new `overlay/overlay-coinor-tools` crate; a live
  headless run of the built binary confirmed `point_to_code` is hidden
  without the three environment variables and, with them set, a real model
  call sent exactly the documented wire shape.
- The arm64 Release build succeeded; `scripts/release/verify-app.sh` and
  `scripts/release/security-scan.sh` passed.

## Artifact

`Coinor-0.6.18-arm64.zip` is an ad-hoc signed, non-notarized personal build
for Apple Silicon running macOS 13 or newer.
