# Conan Code 0.5.25

Makes switching terminal tabs cost only the tab being switched.

## Highlights

- Switching between the tabs of a conversation grew slower the longer Conan
  Code stayed open. Every switch rewrote the whole metadata document to disk,
  rebuilt the entire session catalog, and republished it, which re-rendered the
  full sidebar. That work is proportional to how many conversations and
  projects exist, so the cost of a single click kept climbing even though
  nothing outside the conversation had changed.
- Tab selections are now coalesced per conversation and written once the burst
  of switches settles. Cycling through several tabs performs one write instead
  of one per tab, and the write no longer rebuilds the catalog, because no part
  of the sidebar depends on which terminal tab is selected. A quit or a restart
  still lands any selection that has not been written yet.
- Selecting a managed tab changed no observed state, so the interface had no
  reason to redraw and the switch appeared only when something unrelated
  happened to publish. Managed tab selection is now observed like every other
  tab, and the tab strip repositions without committing an animated scroll on
  each switch.

## Fixes

- Stopping a remote computer's runtime identified the leader by searching its
  whole command line for `grok`, so any process whose path merely contained
  that word matched and was signalled. Conan Code now compares only the
  executable name, which is what distinguishes a leader from an unrelated
  process that happens to live under a directory such as `~/.grok`.
