# Conan Code 0.6.5

A cooked Grok changelog inside Settings, and a subagent-router config synced
to the current model family.

## Grok changelog in Settings

The Settings panel gains a first, non-terminal `Changelog` tab that shows every
published `jattento/grok-build` release plus an `Unreleased` section for work on
the fork's `main` that has not been tagged yet.

- The changelog is cooked into the application bundle at build time by
  `scripts/grok-changelog/cook.py`, so it opens instantly and needs no network
  access. The cooked file is committed as `Coinor/Resources/GrokChangelog.json`.
- Each release is split into the fork's own features and fixes (plain) and the
  changes pulled in from `xai-org/grok-build` (highlighted with a yellow
  background). Validation, security, and release-mechanics boilerplate
  (`cargo test`, `gitleaks`, `codesign`) is filtered out so only features and
  fixes remain.
- Upstream changes are read from the `Changes:` bullet lists inside the
  `Synced from monorepo` commit bodies, so the tab says what xAI changed rather
  than just "Synced from monorepo".
- The `Unreleased` entry compares the last published tag against the fork's
  `main`, deduplicating overlay commits that a published release already
  covers, so a fresh upstream sync shows up the moment it lands.

## Subagent router config sync

The user's `~/.grok/subagent-router.toml` still routed children through the old
`opencode-*` model slugs after the Grok fork moved to the shortened
`alibaba-*` family. The catalog and routes were rewritten to the current slugs
with the `alibabatokenplan` CodexBar provider, preserving vision and
reasoning-effort flags, so subagent routing matches the models the installed
Grok actually serves.

## Validation

- `CoinorTests.GrokChangelogTests`: classification, fork-summary boilerplate
  filtering, upstream-summary extraction, the bundle loader reading the cooked
  JSON, and the shell model wiring.
- `CoinorTests.SettingsFileCatalogTests`: the changelog is the first
  non-terminal tab without a file; every other tab still edits its file with
  `fresh`.
- Full Coinor test suite via `scripts/dev/run-tests.sh` on the pinned
  toolchain (Xcode 26.6, macOS SDK 26.5, Swift 6.3.3).
- `scripts/release/verify-app.sh` on the arm64 Release bundle.
- Security gate (`gitleaks` plus targeted credential/path checks) over the
  repository history, working tree, and the application bundle.

## Artifact

`Coinor-0.6.5-arm64.zip` is an ad-hoc signed, non-notarized personal build for
Apple Silicon running macOS 13 or newer.
