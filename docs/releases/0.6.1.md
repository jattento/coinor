# Conan Code 0.6.1

Fixes automation runs being killed by the application itself, and lets an
automation choose how hard its model thinks.

## An automation run is no longer aborted by a refresh

Installing an automation's launchd job replaced the previous definition
unconditionally: write the plist, `bootout`, `bootstrap`. `bootout` terminates
whatever the job is currently running, so reloading a job that had not changed
killed the run in flight — and the job was reloaded every time the Automations
tab appeared, every time any automation was saved, and immediately before a
forced run. A run that lasted longer than the user's next visit to the tab was
terminated mid-turn, leaving the execution recorded as "in progress" forever
because the job's shell never reached the line that records the outcome.

Installing now compares the generated job with the one on disk and asks launchd
whether it is loaded. An unchanged, loaded job is left completely alone: no
rewrite, no `bootout`, no `bootstrap`. A job is reloaded only when its
definition actually changed or when launchd does not have it.

## Reasoning effort per automation

An automation can now pin a reasoning effort alongside its model — none,
minimal, low, medium, high, extra high or maximum — which is passed to the run
as `--reasoning-effort`. Leaving it at "Model default" keeps Grok's own choice,
which is what every existing automation continues to do.

## Compatibility

Automations stored by earlier versions load unchanged and keep the model's
default effort.

## Validation

- Debug build, Release build, and bundle verification on the pinned toolchain.
- Full test suite: unit and user-interface tests, with no regressions.
- Security gate over Git history, the working tree, and the application bundle.
