# Conan Code 0.6.16

Replaces `NavigationSplitView` with an explicit two-column layout. This is
the fix for the recurring misalignment where the conversation pane rendered
under the sidebar and past the right window edge.

## Root cause, measured

Previous releases reasoned about this from screenshots. This one measured
the live broken window through the accessibility API:

```
WINDOW                        x=-3407  w=1688
  AXSplitGroup                x=-3407  w=1688
    sidebar   AXHostingView   x=-3399  w=264
    AXSplitter                x=-3135  w=0
    detail    AXHostingView   x=-3407  w=1688   ← window origin, full width
      AppShellTerminalRegion  x=-3407  w=1954   ← window width + sidebar width
```

The detail column was placed at the window's own origin with the window's
full width — underneath the sidebar — and its content measured 1954, the
window width plus the sidebar width. That is the whole bug: the pane was
never sized or positioned to the space left over by the sidebar, so its
left edge hid behind the sidebar and its right edge ran off the window.

Because the terminal is the largest thing in that pane, it looked like a
terminal bug. It was not: the plain SwiftUI tab strip was displaced by the
same amount, which is why `main`/`IDE` were invisible while the `+` button
next to them was not.

Neither pinning `columnVisibility` to `.all` nor
`.navigationSplitViewStyle(.balanced)` (0.6.14) prevented it.

## Fix

`AppShellView` lays the two columns out itself:

- An `HStack` gives the sidebar exactly its stored width and the detail
  pane the remainder; both are clipped.
- `SidebarResizeDivider` replaces the split view's splitter, with the width
  clamped to 230...400 and persisted in `AppStorage`.
- A toolbar button (⌃⌘S) replaces the automatic sidebar toggle.
- Window chrome (startup tasks, toolbar, sheets, warning banner, shortcut
  monitor) moved into an `AppShellChrome` modifier so the shell's own body
  stays a plain two-column layout.

Measured after the change, following the reported repro (two chats, send a
message in each):

```
WINDOW                        x=-1700  w=1688
  AppShellSidebar             x=-1700  w=278
  AppShellTerminalRegion      x=-1421  w=1409     (278 + 1 + 1409 = 1688)
```

## Validation

- Reproduced the reported flow first: enter two chats, type and send a
  message in each. Geometry stayed exact.
- Then eight rounds interleaving chat switches with Activity Stack toggles,
  a resize down to 900pt, five more chat switches, and back to full width.
  Re-measured afterwards: sidebar and detail still exactly partition the
  window.
- `scripts/dev/run-tests.sh`: 563 tests in 45 suites. Only the documented
  load-sensitive 5-second wall-clock flakes
  (`oversizedOutputIsTruncatedThroughTheGitRunner`,
  `executableVersionProbeRunsTheAbsoluteBinaryAndRecordsItsOutput`) failed
  under full-suite load; both pass in isolation and their files are
  untouched here.
- Arm64 Release build, `scripts/release/verify-app.sh`, `git diff --check`,
  and the security gate.
